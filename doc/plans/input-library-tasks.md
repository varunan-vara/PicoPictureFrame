# Task split: input library

Status: draft. The design this splits up is in [input-library.md](input-library.md).

How to divide the input library so several people or agents can work at once without stepping on each other. Each task has an owner, the files only that task may edit, what it needs first, and what it hands over.

## Ground rules

1. **Contract first.** Task T0 is done alone and merged before anything else starts. After that, `input.h`, `input_raw_t`, `picoinput.py`'s public names and the vector file format only change through T0's owner.
2. **One owner per file.** A task edits only its own files. Shared files (`CMakeLists.txt`, `pyproject.toml`, the spec) are edited by the integrator (T6) only. If a task needs a change there, it says so in its handover note.
3. **One branch or worktree per task**, named `input/<task>`, for example `input/t2-python`. Merge into `main` only through T6.
4. **Tests are the interface.** A task is done when its checks pass, not when its code looks right.
5. **Hardware is a bottleneck.** Only T5 needs the physical board. Everything else runs on a laptop.

## Dependency graph

```
T0 contract
 |--> T1 vectors + Python tests ----.
 |--> T2 Python library + demo -----+--> T6 integrate
 |--> T3 C logic layer + host test -+       ^
 |--> T4 C hardware glue ---------> T5 bring-up
                                    (needs T3 and T4)
```

T1, T2, T3 and T4 run in parallel once T0 is merged.

## Tasks

### T0 - Contract (sequential, one owner)

- **Edits:** `MenuFirmware/src/input/input.h`, the "API" and "Logic rules" sections of `input-library.md`, `tests/input_vectors/FORMAT.md`
- **Needs:** answers to the open decisions in section 5 of [input-library.md](input-library.md)
- **Does:** writes `input.h` and `input_raw_t`. Fixes the Y-axis sign, the numeric defaults (dead zone, thresholds, lockout time, oversample count) and the vector CSV format, one row per frame: raw inputs in, then expected pressed/held/released bits and the two axis values out.
- **Done when:** the header compiles on its own, and the format doc has one worked example row.

### T1 - Test vectors and Python tests

- **Edits:** `tests/input_vectors/*.csv`, `simulator/tests/`
- **Needs:** T0 merged
- **Does:** hand-writes sample streams from the rules (button bounce, a tap, a hold, a stick drifting inside the dead zone, a stick hovering in the 0.3-0.5 band, a diagonal, an uncentred stick) with expected outputs worked out on paper. Writes a Python test that replays every vector through `picoinput`.
- **Done when:** the vectors are reviewed against the rules (not generated by either implementation), and the test runs, failing only until T2 lands.

### T2 - Python library and demo

- **Edits:** `simulator/picoinput.py`, `simulator/example_app.py`
- **Needs:** T0 merged
- **Does:** implements the logic layer and the keyboard source behind the contract's names. Adds a demo to the example app: move a box with the stick, flash on A and B, show held states.
- **Done when:** the demo works in the simulator, and the T1 test passes (once T1 is in).

### T3 - C logic layer and host test

- **Edits:** `MenuFirmware/src/input/input.c`, `MenuFirmware/tests/`
- **Needs:** T0 merged
- **Does:** implements `input_step()` and the query functions with no Pico SDK calls. Writes a host program (plain `cc`, no SDK) that reads the vector CSVs and compares outputs.
- **Done when:** the host test passes every vector. Needs no hardware.

### T4 - C hardware glue

- **Edits:** `MenuFirmware/src/input/input_hw.c`
- **Needs:** T0 merged
- **Does:** `input_init()` pin setup (inputs with `gpio_pull_up()`, ADC0 on GP26, ADC1 on GP27), a function that fills an `input_raw_t` (including oversampling and the timestamp), and centre calibration. Requests the `CMakeLists.txt` change from T6.
- **Done when:** it builds for the Pico. It can't be checked until T5.

### T5 - Hardware bring-up and tuning

- **Edits:** a small debug program or `#ifdef` block, and the numeric defaults in `input.h` (through T0's owner)
- **Needs:** T3 and T4 merged, the wired board
- **Does:** prints raw ADC values and button states over serial. Checks the centre and the range of each axis, the direction of each axis, and how much the buttons bounce. Tunes the dead zone, thresholds and lockout time on the real stick.
- **Done when:** a stick at rest reads exactly 0, full deflection reaches 1.0, a diagonal triggers two directions, and one button tap gives one press.

### T6 - Integration (the integrator)

- **Edits:** `CMakeLists.txt`, `pyproject.toml`, `doc/Specification and Design.md`, `doc/README.md`, and merges for all tasks
- **Needs:** whichever tasks are ready
- **Does:** merges the branches, adds the new sources and test target to the build, adds the API table to the spec, and wires the library into `main.c`'s menu. Runs the cross-check: the same vectors through Python (T1+T2) and C (T3) must agree.
- **Done when:** both test runs are green on `main` and the menu navigates with the real inputs.

## Hand-over note

Each task ends with a short note (in the branch's last commit message or the PR description) listing: what changed, what to run to check it, and anything another task now has to do. This is what lets someone pick up a task without reading the whole history.
